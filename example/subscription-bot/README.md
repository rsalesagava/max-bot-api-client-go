# Бот проверки подписки на канал (Max)

Бот для мессенджера Max, который выдаёт пользователю ссылку на подборку товаров
только после подписки на канал [@megastroy_diy](https://max.ru/megastroy_diy).

Без базы данных: все пользователи, запустившие бота, дописываются в обычный текстовый файл.

## Как работает

1. Пользователь запускает бота (кнопка «Начать» или любое сообщение).
2. Бот записывает пользователя в файл `users.txt` (один раз, повторные запуски не дублируются).
3. Бот проверяет, подписан ли пользователь на канал:
   - **подписан** — сразу присылает кнопку «🛒 Открыть подборку» со ссылкой
     `https://megastroy.com/catalog/groups?products_groups%5B%5D=22`;
   - **не подписан** — просит подписаться и присылает кнопки
     «📢 Подписаться на канал» и «✅ Я подписался».
4. По нажатию «✅ Я подписался» подписка проверяется повторно: если она есть —
   сообщение с просьбой подписаться заменяется на сообщение с подборкой, если нет —
   показывается уведомление «Подписка не найдена».
5. Если пользователь подписался на канал уже после запуска бота, бот присылает подборку сам
   (по событию `user_added` из канала).

Посты канала и сообщения в групповых чатах бот игнорирует.

## Подготовка

1. **Создайте бота и получите токен** на платформе [MAX для бизнеса](https://business.max.ru/)
   (раздел «Чат-боты» → ⋮ → «Настройки» → скопировать токен).
2. **Добавьте бота в администраторы канала** `@megastroy_diy`. Без прав администратора
   Max не позволяет боту получать список участников канала, а значит — проверять подписку.
3. При необходимости установите в систему корневой сертификат Минцифры
   (Max API работает по TLS с сертификатами российского УЦ). Если добавить его в системное
   хранилище нельзя, укажите путь к PEM-файлу в переменной `CA_CERT_FILE`.

## Настройка

Все параметры задаются через переменные окружения:

| Переменная     | Обязательна | По умолчанию                                                     | Описание                                                                                 |
|----------------|-------------|------------------------------------------------------------------|------------------------------------------------------------------------------------------|
| `BOT_TOKEN`    | да          | —                                                                | Токен бота                                                                               |
| `CHANNEL`      | нет         | `@megastroy_diy`                                                 | Канал для проверки подписки: `@name`, `name` или `https://max.ru/name`                   |
| `CHANNEL_ID`   | нет         | определяется по `CHANNEL`                                        | Числовой идентификатор канала — укажите, если бот не смог определить его по имени        |
| `CATALOG_URL`  | нет         | `https://megastroy.com/catalog/groups?products_groups%5B%5D=22`  | Ссылка на подборку товаров                                                               |
| `USERS_FILE`   | нет         | `users.txt`                                                      | Путь к текстовому файлу с пользователями                                                 |
| `CA_CERT_FILE` | нет         | —                                                                | PEM-файл с дополнительным корневым сертификатом (например, Минцифры)                     |
| `MAX_API_URL`  | нет         | боевой адрес API                                                 | Адрес Bot API — только для тестов и отладки                                              |

### Как узнать `CHANNEL_ID`

Обычно не требуется: бот сам определяет идентификатор канала по его публичному имени.
Если в логе появилось предупреждение `не удалось определить канал`, добавьте бота в канал
(или удалите и добавьте заново) — при событии `bot_added` бот выведет в лог строку вида

```
бот добавлен в канал «МЕГАСТРОЙ» (chat_id=-70000000000007, link=https://max.ru/megastroy_diy)
```

и, если ссылка канала совпадает с настроенной, начнёт использовать этот `chat_id` сразу.
Чтобы не зависеть от этого при перезапусках, пропишите значение в `CHANNEL_ID`.

## Запуск

```sh
# из корня репозитория
export BOT_TOKEN='токен_бота'
go run ./example/subscription-bot
```

Сборка бинарника:

```sh
CGO_ENABLED=0 go build -o subscription-bot ./example/subscription-bot
BOT_TOKEN='токен_бота' USERS_FILE=/var/lib/subscription-bot/users.txt ./subscription-bot
```

Остановка — `Ctrl+C` или `SIGTERM`, бот завершается корректно.

### Пример unit-файла systemd

```ini
[Unit]
Description=Max subscription bot
After=network-online.target

[Service]
ExecStart=/opt/subscription-bot/subscription-bot
WorkingDirectory=/opt/subscription-bot
Environment=BOT_TOKEN=токен_бота
Environment=USERS_FILE=/opt/subscription-bot/users.txt
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

## Файл пользователей

`users.txt` — текстовый файл, одна строка на пользователя, поля разделены табуляцией:

```
2026-09-21 14:05:00	123456789	@username	Иван Петров
```

Поля: дата и время первого запуска, `user_id`, username (или `-`), имя.
Файл можно открыть в любом табличном редакторе как TSV. При старте бот перечитывает файл,
поэтому после перезапуска пользователи не дублируются. Строки, добавленные вручную
(комментарии, пустые строки), игнорируются.

## Тесты

```sh
go test ./example/subscription-bot/
```

Тесты поднимают эмулятор Max Bot API на `httptest` и проверяют все сценарии:
запуск бота подписанным и неподписанным пользователем, нажатие «Я подписался»,
автоматическую выдачу подборки после вступления в канал, игнорирование постов канала,
запись пользователей в файл и его повторное чтение.
